## Capabilities

- **Camera**: live stream, configurable resolution and frame rate, photo capture
- **Audio**: microphone input, audio output
- **Display** (Ray-Ban Display only): UI primitives reported as text, images, lists, buttons,
  video playback. Exact component set needs verification against the 0.9 API reference.
- **Session management**: device session states, pause/resume, availability
- **Permissions**: app registration flow + per-capability permission requests

## Platform requirements

- iOS 15.2+, Xcode 14.0+
- Android 10+, Android Studio Flamingo or newer

## No App Store publishing required

Confirmed in the docs: Developer Mode "allows your unpublished app to register and interact with
your AI glasses without the need to submit it for publishing review."

A debug build signed with your own team, installed from Xcode to your iPhone, connects to the glasses.
Registration is with **Meta**, not Apple. TeamID and bundle ID are identity only. No review, no
TestFlight, no store listing needed for personal development.

## Config keys the SDK needs

**iOS** (Info.plist or Xcode UI):
- `AppLinkURLScheme`
- `MetaAppID`      <- autogenerated by Wearables Developer Center
- `ClientToken`    <- autogenerated by Wearables Developer Center
- `TeamID`

**Android** (manifest meta-data):
- `APPLICATION_ID`
- `CLIENT_TOKEN`
- Permissions: `BLUETOOTH`, `BLUETOOTH_CONNECT`, `INTERNET`

## Registration vs permissions: two separate things

1. **Registration** — the app registers with the Meta AI app as a permitted integration.
   Developer Mode makes this automatic. Outside Developer Mode, users must be in a release channel.
2. **Permissions** — only after registering can the app request device capabilities. The user sees a
   prompt in the Meta AI app and picks "Allow once" (temporary) or "Allow always" (persistent).

This flow behaves the same in dev as in production, so the permission-denied paths still have to be
built and tested.

## Key constraint: one app at a time

> "For security purposes, only one 3rd party app can remain registered at a time in Developer Mode."

Registering a second app silently unregisters the first. Prototyping two ideas in parallel means
bouncing between them. Worth remembering when something that worked yesterday stops working.

## MockDeviceKit

Test without hardware: pair a mock device, change its state, simulate permissions and media
streaming. **Does not support display glasses**, so all display work requires the real device.
